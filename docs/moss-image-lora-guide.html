1先懂這顆模型

有五件事跟其他模型不一樣，照抄舊設定一定出錯。

① 它不是 CFG 蒸餾模型

官方推論用 CFG 3.0（範圍 3–6）。

設成 1.0 會變成單次 forward，連跳層指引都沒有，畫面會偏平。

② 邊長是 16 的倍數

VAE 8× 下採樣再乘上 2×2 patch，有效 stride 16 px。

不是 32。dataset 解析度與寬高都受此限制。

③ 文字編碼器凍結

Qwen3.5-9B，走 chat template，上限 4096 token。

caption 用「句子」比逗號 tag 串更貼近它看過的資料。

④ 負向分支跳過 block 22

這是 SLG（跳層指引），LoRA 預設也要排除 layers.22.。

目的是不破壞 CFG 的對比；放錯層級不會報錯，也不會生效。

⑤ 預設底模是 SFT，但人物要選 Base

ai-toolkit 預設「MOSS-Image SFT」，但那只是預設值。

Base 沒有做過 CFG 蒸餾，保留了完整訓練資訊，官方就是為社群訓 LoRA 而留的。

⑥ 它收斂得慢

300 步就能認人，但 1500–1600 步都還在進步。

所以不能只看最後一顆 checkpoint，每 250 步都要留。
最容易被抄錯的一格 上一顆模型（Qwen-Image-2.1）的預覽 guidance_scale 是 1.0，因為它是 CFG 蒸餾模型。 MOSS 完全相反：3.0。把 1.0 搬過來，你會在完全沒有 CFG 的狀態下判斷 LoRA 好壞。

2資料集怎麼挑

張數是上限，多樣性才是變數。

張數：30–60 張，目標 40

可查證的人物案例是 56 張（1200 步、單卡約 65 分鐘）、62 張、53 張。 工具方另有「25 張有變化勝過 60 張近重複」的說法——兩者不衝突： 重複的構圖與背景會被併進「這個人」的概念裡，所以上限是張數，變數是多樣性。

取景比例：半身 50 / 全身 30 / 特寫 20

這是唯一有公開逐張統計的人物案例。要注意的是它仍然有缺口——作者自評「朝左的角度太少，側臉只有 4 張」。 同一作者前一次用「以頭肩照為主」的資料集，結果訓練久了會把全身 prompt 拉回大頭照。

維度建議為什麼
取景半身 50%、全身 30%、特寫 20%缺全身，構圖會被鎖在胸部以上
角度正面為主，側臉至少 8–10 張最常見的缺口，補齊後側臉 prompt 才聽話
服裝4–6 套，平均分配單一服裝佔比過高會有外洩風險
光源室內外、順光逆光都要有膚色被拉平通常是光源樣本太單一
背景至少 5 種不同場景同一面牆會變成「這個人」的一部分

解析度與裁切

  • 不要自己裁切。loader 會自動分桶縮放，而且不會放大——原圖太小就是浪費。
  • 原圖長邊至少 1024 px，否則那張圖注定只能餵小 bucket，臉部細節會被抹掉。
  • square_crop 保持 false。設成 true 會關掉分桶、每張中央裁成正方形。
  • 面積以 1 MP 為目標（1024×1024、880×1168、832×1248 都在這個範圍）。
一定要剔除的照片 近重複（同一張換濾鏡）、模糊或壓縮痕跡重、多人合照、被遮住半張臉、臉太小（全身照裡只佔一小角）、 有浮水印或字幕、重美顏（皮膚已無紋理）、大量背影。

3Caption 怎麼寫

格式沒有共識，但「內容」有——這是官方與社群唯一完全一致的地方。

唯一鐵律 不要描述觸發詞已經代表的外觀。髮色、瞳色、臉型、身材、年齡，全部不要寫。 你要讓 LoRA 從圖片學這些，寫進 caption 等於用文字硬拉，會削弱學習效果。
要寫不要寫
場景（street、cafe、studio）長相（臉型、眼睛大小、鼻子）
服裝（white shirt、denim jacket）髮色、瞳色
光線（window light、backlit、overcast）身材、身高、體型
角度與取景（profile、full body、close-up）「beautiful」「attractive」這類評價詞
動作與表情（laughing、looking at camera）畫質詞（8k、masterpiece、best quality）

格式：用句子，不要用 tag 串

MOSS 的官方文件同時接受自然語言、tag 串與 JSON layout，社群也確實有人用 tag 串成功。 但它的文字編碼器是走對話模板的 Qwen3.5-9B，句子更貼近它訓練時看到的東西。 tag 串不是錯，只是沒有理由優先選它。 

mychar, a woman standing in a bright cafe, wearing a white knit sweater, soft window light from the left, three-quarter view, shallow depth of field, candid expression
  • 觸發詞放句首，而且每張都要有。ai-toolkit 找不到時會自動補到最前面，但自己寫清楚比較不會出意外。
  • 長度抓 40–90 個英文詞就夠。官方預訓練語料的中位數大約 75 token，人物 caption 不需要長篇。
  • 用英文寫。模型看過的英文資料量最大。
  • 一張圖一個場景描述，不要把所有可能都寫進去。

4Job 參數設定

下面這份可以直接貼進 ai-toolkit 的 job 設定，改成你的路徑與觸發詞即可。

UI 預設有三個陷阱，開工前先改掉
  • resolution: [512, 768, 1024] — 清單會拆成三份資料集，同一批圖跑三種解析度，步數預算等於 ×3。
  • caption_dropout_rate: 0.05 — 通用防過擬合值；人物小資料集建議改 0。
  • 預設底模是 SFT，要自己切到「MOSS-Image Base」。
job: extension
config:
  name: moss_char_lora_v1        # 輸出資料夾與檔名；重訓請改這裡
  process:
    - type: diffusion_trainer
      training_folder: output
      device: cuda:0
      trigger_word: "mychar"

      network:
        type: lora
        linear: 32
        linear_alpha: 32
        network_kwargs:
          ignore_if_contains: ["layers.22."]   # 不訓 CFG 負向分支跳過的層

      save:
        dtype: bf16
        save_every: 250
        max_step_saves_to_keep: 6      # 預設 4；人物常要回頭撿早期 checkpoint

      datasets:
        - folder_path: /workspace/dataset
          caption_ext: txt
          caption_dropout_rate: 0.0    # 人物小資料集建議 0
          buckets: true
          resolution: [1024]             # 16GB 改 [768]；不要留 [512,768,1024]
          cache_latents_to_disk: true
          cache_text_embeddings: true  # 關鍵：讓 9.75GB 的文字編碼器不必常駐

      train:
        batch_size: 1
        steps: 2500                    # 20–30 張人物：2000–3000
        gradient_accumulation: 1
        train_unet: true
        train_text_encoder: false      # 架構內已硬凍結
        gradient_checkpointing: true
        noise_scheduler: flowmatch
        timestep_type: shift
        optimizer: adamw8bit
        lr: 0.0001
        lr_scheduler: constant
        dtype: bf16

      model:
        name_or_path: OpenMOSS-Team/MOSS-Image-Base
        arch: moss_image
        quantize: true
        qtype: convrot8
        quantize_te: true
        qtype_te: convrot8
        low_vram: true
        layer_offloading: false        # 16GB 改成 true
        model_kwargs:
          uncond_skip_layers: [22]      # 官方 SLG

      sample:
        sampler: flowmatch
        sample_every: 250
        width: 1024                    # 16GB 可降 768
        height: 1024
        guidance_scale: 3.0            # 不是 1.0
        sample_steps: 30               # 驗收時改 50
        seed: 42
        neg: ""

注意：真正決定 Base 還是 SFT 的是 name_or_path，不是 arch 的標籤。 arch 只用來挑 UI 預設，載入時標籤會被切掉。

5記憶體級距

模型的靜態大小決定了下限：DiT 5.4GB（int8）＋ 文字編碼器 9.75GB（int8）。

顯卡可行設定結論
24GB
3090 / 4090		 兩個 convrot8、解析度 1024、layer_offloading: false 可行。不量化也能跑，但要 cache_text_embeddings: true 把 19GB 的編碼器移出 GPU
16GB
4080 / 5070 Ti / 5080		 兩個 convrot8、low_vram: true、layer_offloading: true、解析度 768 這條路線的實務下限
12GB
3060 / 4070		 不建議 大概率 OOM；其他訓練器能用是靠 block swap，ai-toolkit 沒有這個機制
省 VRAM 的優先順序 cache_text_embeddings（把 9.75GB 編碼器移出）→ 降 dataset 解析度 → 降預覽寬高 → 最後才開 layer_offloading（每層往返 CPU，速度掉最多）。

另外：low_vram 和 layer_offloading 是兩個獨立開關。 前者是把模型載到 CPU，不是「自動分批」。

6訓練中怎麼看

預覽圖是草稿，不是成績單。

你會看到意思該做什麼
300 步左右就認得出人正常，身分很早進來繼續跑，別急著停
1500 步還在變好正常，MOSS 收斂慢跑到 2000–3000 再比較
loss 一直在 0.4–0.65正常，這個 loss 看不出收斂看圖，不要看曲線
預覽邊緣軟、文字糊可能只是 30 步不夠同一 seed 用 50 步重跑再判斷
每張都長一樣、皮膚像蠟過擬合退回更早的 checkpoint
不寫觸發詞也像本人概念外洩降 rank、減步數、加資料多樣性
最容易誤判的一件事 預覽預設只跑 30 步，官方推論建議 ≥50 步。 用 30 步的圖去判斷「這顆 LoRA 不夠好」，會低估它。驗收時一定要用 50 步重跑同一組 seed。

7訓練後怎麼驗收

用固定的三路對照，一次只改一個變數。

  1. 原模型（不套 LoRA）跑同一組 prompt — 這是 baseline，用來扣掉模型本身的審美傾向。
  2. 套 LoRA、不寫觸發詞 — 檢查有沒有概念外洩。
  3. 套 LoRA、寫觸發詞 — 這才是你實際會用的情境。
驗收項目怎麼看
相似度正面、側面、四分之三角度各一張；與本人照片並排
體態全身照對照肩寬、腰線、髖寬、腿長比例——注意模型本身就會把人修得好看一些
泛化測一組訓練集沒有的構圖（例如資料集全是室內，就測戶外全身）
文字能力畫面裡放一段文字，看有沒有糊掉或拼錯
外洩第 2 路若也像本人，就是外洩

選 checkpoint 的方式：把 250 步間隔的每一顆都跑同一組 prompt、同一個 seed， 挑「相似度夠、又還沒開始僵化」的那一顆。不要直接拿最後一顆。

8常見問題

訓練到一半 OOM，但看不出是哪一階段

載入、訓練、取樣三個階段的峰值不同，要分開處理：

  • 載入時 → 開量化 + low_vram
  • 訓練時 → 降 dataset 解析度（1024 → 768）
  • 取樣時 → 降 sample.width/height，不必動 dataset
同一份設定再跑一次，馬上就結束了

它會從 output/<name>/ 最新的 checkpoint 續訓。改 config.name，或把舊輸出目錄搬走。

LoRA 在 ComfyUI 裡完全沒效果，console 一直印 lora key not loaded

舊版 ComfyUI（0.42.5）的 MOSS 分支只認 diffusion_model. 前綴的 key。 更新到 master 即可（PR #17296 已修）。ai-toolkit 產出的檔案本來就帶前綴，不受影響。

為什麼不能用 Turbo / DMD 版本當預覽基準？

那是蒸餾過的另一條路線，步數與 CFG 都不同（4–8 步、CFG 1）。用它看到的畫面， 不能用來判斷你正在訓的這顆 LoRA。預覽與驗收一律用 base 模型、30／50 步、CFG 3。

訓練完的 LoRA 要放哪一顆底模出圖？

用 SFT。訓練在 Base、出圖在 SFT 是目前的共識做法。

為什麼我的圖有淡淡的垂直條紋？

那是 SFT 模型本身的特性，不是你的訓練造成的。可以在推論端疊 DeBand LoRA，或直接用 Base。
